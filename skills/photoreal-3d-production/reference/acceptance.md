# 验收标准

一个素材、场景或主持人要给孩子看，必须依次通过 A（自动检查）、B（对照图）、C（家长确认）、D（agent 自检），并尽量做 E（iPad 实测）。A 里的检查由实现的 agent 写进仓库，作为测试一直跑。

现在能跑的命令：

```
pnpm -s dls asset-check                 # 只查 A5：场景代码里的几何体都在白名单里，列出还在等替换的
pnpm -s dls asset-check <asset_id> --save   # A1–A9，结果写进 manifest.json 的 stats 和 checks
pnpm -s dls asset-sheet <asset_id>      # 对照图 content/assets/<asset_id>/sheet.png
```

自动的：A1（Khronos glTF Validator）、A2、A3（模型最大边和 `real_scale_m` 最大值比）、A4、A5、A6（来源、作者、许可、日期、sha256、形态依据，生成类 ≥ 3 张参考照片）、A7（有动画就要有 `motion_refs`）。要人看的：A7 的关节限位和速度、A8（组件测试）、A9（跑测试）。

## A. 自动检查（`pnpm -s dls asset-check <asset_id>`，并纳入 `pnpm test`）

| 编号 | 检查 | 不通过 |
| --- | --- | --- |
| A1 | GLB 用 Khronos glTF Validator 检查，0 个错误 | 修文件 |
| A2 | 主角的每个材质都有底色、法线、ORM 贴图；没有只给一个颜色、一个粗糙度数值的主角材质 | 补贴图 |
| A3 | 包围盒尺寸和登记的 `real_scale_m` 相差 ≤ 5% | 改比例或改登记（要有出处） |
| A4 | 三角形数、绘制调用、贴图尺寸、文件大小在 [component-contract.md](component-contract.md) 的预算内 | 减面、出 LOD、压缩贴图 |
| A5 | **代码几何检查**：`packages/components/src/` 里出现 Box、Sphere、Cylinder、Capsule、Lathe、Torus、Cone、Tube、Extrude、Icosahedron、RoundedBox 等几何体，所在文件必须在白名单里，并逐个写明是哪一种“简单几何件”（[realism-spec.md](realism-spec.md) 第 1 节）。复杂物体一个都不能有 | 换成素材文件 |
| A6 | 登记完整：来源网址、作者、许可、下载日期、sha256；生成类有 ≥ 3 张参考照片和生成器名称版本；有形态核对依据 | 补登记，补不齐就不用 |
| A7 | 动作：机器人轨迹按 120 Hz 采样，关节角度不超限位、速度不超厂家数据表；动物有动作依据视频；播放慢于真实速度时画面上有“放慢 N 倍” | 改轨迹或补标注 |
| A8 | 数学一致：`still(params)` 摆出的数量、长度、面积和参数一致（例如 rows × cols 个零件） | 修组件 |
| A9 | `pnpm test`、`pnpm typecheck`、`pnpm e2e:apps` 全部通过，页面没有控制台报错 | 修 |

A5 的白名单文件：`packages/components/src/simple-geometry.allow.json`，格式 `{ "<文件>": [{ "geometry": "RoundedBoxGeometry", "what": "3 cm 实木积木", "class": "简单几何件" }] }`。改白名单要在交付说明里写原因，家长能看到。

## B. 对照图（自动生成 `content/assets/<asset_id>/sheet.png`，`pnpm -s dls asset-sheet <asset_id>`）

参考照片写在 `manifest.json` 的 `reference_photos`，每张写 `angle`（“3/4 前侧”“正侧”“俯视”“特写”），对照图按角度配对；没写角度的按顺序填空位。现在的命令用工作室光照渲染 4 个角度，动作行（5 帧）和课里光照的渲染还没做（gaps.md G7）。


- 左边是我们的渲染，右边是同角度的真实照片，每个主角至少 4 组：3/4 前侧、正侧、俯视、最有细节的部位特写。
- 有动作的，再加一行 5 帧（0%、25%、50%、75%、100%），旁边放参考视频的对应帧。
- 用 Pad 的分辨率和课里实际的光照、镜头渲染，不单独打光“摆拍”。
- 对照图在家长端「素材确认」里显示，和这个素材要出现的课的预览放在一起。

## C. 家长确认

- 家长端每个待确认素材有两个按钮：“确认可用”和“退回”（写一句原因）。只有“确认可用”能把状态改成“采用”。
- 退回的原因写进 `manifest.json` 的 `reviews`；下一版必须针对原因改，并在交付说明里逐条回应。
- 家长的判断标准：看上去像照片或纪录片，不像动画片；主角就是课讲的那个东西；尺寸和动作像真的。

## D. agent 交给家长前的自检

每条都回答“是”才能交：

1. 做之前按 research.md 收集、理解、整理过：`sources.json`、`brief.md`、`plan.md` 都写了，3D 来源比较过所有候选？
2. 画面里每个复杂物体都来自素材文件，不是代码拼的？
3. 主角就是课讲的那个东西，不是别的东西代替，也不是只在文字里？
4. 所有材质都有贴图，有真实的磨损和粗糙度变化？
5. 尺寸是真实的，有出处？
6. 动作有依据（真实视频或厂家数据），速度真实或标了放慢倍数？
7. 没有挤压拉伸、弹跳、表情脸、拟人手势？
8. 光照用的是和场景相符的实拍 HDRI，有接触阴影？
9. 每个素材的来源和许可都登记了，许可允许我们这样用？
10. 生成类素材有 ≥ 3 张参考照片，标了“AI 依据照片生成”？
11. 对照图里，渲染和真实照片放在一起不显得假？
12. 没有把孩子的任何信息发给外部服务？
13. A1–A9 全部通过？

可以加一道参考性的盲测：把渲染图和真实照片混在一起，让看图模型判断哪些是渲染的；它一眼就挑出来的，先自己改。这不能代替家长确认。

## E. iPad 实测

- 帧率：目标 60，最低 30。
- 首次加载 ≤ 8 秒（家里 Wi-Fi），缓存后 ≤ 2 秒。
- 一节 20 分钟的课从头走到尾不崩、不发烫降频到卡顿。
- 实测结果写进交付说明；没条件实测就写“未在 iPad 实测”，不要估。
