# 写实规格

判定标准：截图放进纪录片、产品照片或博物馆展板里不违和，家长一眼看上去不像动画片。下面的条目是做到这一点的最低要求，全部满足也还要家长确认。

## 1. 什么可以用代码做，什么必须是素材文件

| 类别 | 例子 | 怎么来 |
| --- | --- | --- |
| 复杂物体 | 工业机械臂、服务机器人、动物、人、车辆、建筑、桥梁、隧道、植物、电器 | **只能**是模型文件（GLB）或视频：扫描、厂家 CAD、专业模型、依据真实照片生成。代码不得拼出它们的任何可见部分 |
| 简单几何件 | 积木方块、地砖、样方框、管子、玻璃板、绳子、卷尺带、托盘平板 | 可以代码生成几何，但必须：倒角（半径 ≥ 实物的 1%，至少 0.5 mm）、扫描或实拍来源的 PBR 贴图、磨损和脏污、按实物尺寸 |
| 地面与环境 | 混凝土地面、沙地、草地、海底 | 扫描贴图（ambientCG、Poly Haven 等）铺地面；石头、植物、珊瑚等散布物是复杂物体，用模型文件 |
| 数学标注层 | 行列标签、数字、虚线框、高亮、计数 | 代码绘制，做成界面元素（标签牌、描边），明显是“标注”，不伪装成实物 |
| 测量工具 | 卷尺、直尺、量角器 | 实物外形用模型或简单几何件规则；刻度用真实刻度贴图 |

代码里拼几何体的检查方法见 [acceptance.md](acceptance.md) A5。

## 2. 通用要求

### 几何

- 单位是米，按真实尺寸放（误差 ≤ 5%）。每个素材登记 `real_scale`，场景里的包围盒要和它一致。
- 没有完全锐利的边：真实物体都有倒角或圆角。扫描和专业模型自带，代码几何件按上表做。
- 细节密度：离镜头最近时占画面一半以上的主角，面数 5 万–30 万三角形；远景物体用低细节版本（LOD）。
- 物体之间不穿插、不悬空。接触处有接触阴影或烘焙的环境光遮蔽（AO）。

### 材质和贴图

- 一律用金属度 / 粗糙度 PBR。主角每个材质至少有：底色贴图、法线贴图、ORM（遮蔽 / 粗糙度 / 金属度）贴图。只给一个颜色、一个粗糙度数值的材质，不能用在主角上。
- 贴图来源是扫描、实拍或厂家资料，不是手画的纯色块。主角贴图 2K–4K，用 KTX2（Basis）压缩。
- 要有真实世界的不完美：粗糙度的变化、划痕、灰尘、指纹、油漆的橘皮纹、塑料的注塑纹、金属的拉丝。
- 颜色在真实范围内：底色亮度（sRGB）在 30–240 之间，不用纯白、纯黑、高饱和的“玩具色”。
- 软组织（虫体、皮肤、肉质部分）用次表面散射；海洋生物和湿润表面有湿润高光；玻璃、面罩用真实折射和反射。
- 只有屏幕、指示灯这类本来就发光的东西可以用自发光材质，亮度和真实设备相当，不加夸张的光晕。

### 光照

- 环境光用真实拍摄的 HDRI，和场景对得上：工厂用厂房 HDRI，室内用室内 HDRI，户外用户外，海底用海底光照（蓝绿色衰减、水面焦散、悬浮颗粒、远处雾化）。
- 一盏主光和 HDRI 里的太阳或主光源方向一致，软阴影。
- 静止的环境（地面、墙、设备底座）在 Blender 里烘焙光照贴图和 AO，实时只算会动的东西。
- 曝光固定，按真实场景的亮度调，不忽明忽暗。

### 镜头

- 视场角 30°–55°（相当于全画幅 35–70 mm），不用鱼眼。
- 机位高度合理：桌面场景从坐着的大人视线高度看，大场景从站立的人眼高度看；俯视只在讲平面图时用。
- 镜头移动平稳、有阻尼，像人拿着稳定器或摄影机轨道；不旋转着飞来飞去，不快速切换。
- 可以有轻微景深，焦点在主角上。

### 后期

- 色调映射 ACES Filmic 或 AgX，输出 sRGB，有抗锯齿。
- 不描边、不卡通着色、不加漫画效果线、不加贴纸和表情。
- 光晕只给指示灯和屏幕，且很弱。

### 动作

- 物理上说得通：有重量、有惯性，接触时不穿模，抓起的东西跟着夹具走，放下时落稳。
- 机器的运动用 S 形或梯形速度曲线（平稳加速、匀速、平稳减速），不弹跳、不过冲。
- 生物的动作依据真实视频（登记视频来源），速度是真实速度；太快看不清的放慢，并在画面上标“放慢 N 倍”。
- 不用动画片手法：挤压拉伸、弹跳、夸张预备动作、眨眼卖萌、拟人表情和手势（工业机器人不招手）。

## 3. 按主角类型

### 3.1 工业机器人和机械

- 用真实存在的型号（例如 Universal Robots UR5e、KUKA KR 系列、ABB IRB 系列、FANUC LR Mate 系列），几何来自厂家 CAD 或基于 CAD 的专业模型，按型号的真实尺寸。
- 材质：喷漆铸件（漆面有轻微橘皮纹和粗糙度变化）、机加工铝件、橡胶密封圈、线缆和接头、底座螺栓、铭牌。家用阶段可以保留厂家标识；商用前去掉商标或取得授权。
- 末端执行器也用真实产品模型（真空吸盘组、两指夹爪等），吸盘有橡胶材质和形变。
- 运动：用这个型号真实的运动学（URDF 或 DH 参数），关节不超出厂家数据表的限位和最大速度。抓取和放下的最后一段走直线，接近和离开有减速。一个抓放循环 3–6 秒，和真实生产线相当；放慢要标出。
- 工作站周边：真实的传送带、安全围栏、地面警示线、工件（齿轮等从 CAD 来，机加工金属贴图）。
- 不加眼睛、表情，不做招手、点头等拟人动作。

### 3.2 服务机器人（接待、送餐、扫地等）

- 用真实存在的产品外形和比例，模型来自扫描、厂家资料或基于真实产品照片的专业建模。
- 材质：磨砂或半光 ABS 塑料（有注塑纹和细微划痕）、有真实反射的玻璃面罩、带像素结构的显示屏。屏幕上显示的内容就是真实产品屏幕会显示的界面。
- 动作只做真实产品能做的：底盘移动、头部转动、手臂关节（如果真实产品有），速度和真实产品一致。
- 作为主持人时的要求见 [host.md](host.md)。

### 3.3 动物

- 真三维模型：标本扫描，或依据至少 3 张不同角度的真实照片（俯视、侧视、正视）生成后由人修整。只有俯视一张照片做出来的浮雕，只能在镜头始终从上往下看（俯角 ≥ 60°）时用，侧面一看就是扁的。
- 形态核对：体节数、足的对数、触角、口器、颜色斑纹和这种动物的科学描述一致，登记核对依据（图鉴、论文、博物馆页面）。
- 材质：甲壳的硬质高光、软体的次表面散射、海洋动物的湿润感、刚毛和细毛用毛发或透明贴图。
- 骨骼按真实解剖绑定，动作依据真实视频。会出洞、伏击、游动的，按视频里的方式和速度。
- 环境是它真实的栖息地（底质、深度对应的光照、伴生生物），登记依据。不借用其他动物的场景。

### 3.4 人（真人主持人）

见 [host.md](host.md)。只用实拍视频或依据成人照片生成的写实数字人，不用卡通形象、低多边形人物或游戏风格人物。

### 3.5 建筑、桥梁、隧道

- 来自真实结构的倾斜摄影、BIM / CAD 或专业模型，按真实尺寸。讲某座真实的桥就用那座桥的资料，并登记出处。
- 材质：风化混凝土、锈蚀和镀锌钢、沥青、玻璃幕墙的真实反射。
- 远景可以用实拍照片或 HDRI 做背景。

### 3.6 环境和道具

- 地面和墙面用扫描贴图；石头、植物、珊瑚、家具、工具等用模型文件。
- 环境要“有人用过”：灰尘、磨损、散落的小东西，不要样板间那样干净一律。

## 4. 实时做不到时

iPad 上实时渲染的写实程度有限。下面这些优先**预渲染**（Blender Cycles 路径追踪）或用实拍视频，实时部分只留孩子要动手操作的东西：

- 开场镜头、动物出击的特写、机器人工作的全景。
- 课末主持人（见 [host.md](host.md)）。
- 需要毛发、水、烟雾、大量反射的画面。

预渲染视频：1920×1080 或 Pad 屏幕分辨率，H.264 / HEVC，循环片段首尾无缝；和实时场景用同一套模型、贴图、HDRI，切换时看不出两套画面。

| 退回的东西 | 问题 | 应该怎么做 |
| --- | --- | --- |
| 程序拼的孔雀螳螂虾 | 几何体拼的身体，像动画片 | 依据照片的写实图或扫描模型 |

| 机器人课里出现积木 | 拿积木冒充机器人 | 主角就是机器人本身 |
| 博比特虫的课用螳螂虾的海底场景、虫只出现在文字里 | 主角看不到、场景不对 | 博比特虫的真实 3D 和它自己的栖息地 |
