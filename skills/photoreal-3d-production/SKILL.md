# photoreal-3d-production

这份 Skill 写给**实现画面的 agent**（Codex、Qoder、Cursor、Claude Code 等）和做素材的人。它规定孩子在 Pad 上看到的每一样东西要做到什么程度、从哪里来、怎么接进课里、怎么证明做到了。做课（写 LessonSpec）的规则在 `skills/discovery-learning-studio/`，两份 Skill 分工：做课的只写课、把主角列进待制作；这里负责把主角和场景做出来。

规则只写在 `skills/photoreal-3d-production/`，别处只放入口。

## 目标

家长只说“给妹妹做一节机器人的课”或“哥哥想学博比特虫”，系统就自己找教材位置、定数学目标、找或做写实素材、搭 3D 场景、写课、给挑战题配图、由主持人带孩子聊完，最后交给家长在家长端点按钮确认。中间不停下来要资料，不让家长敲命令。

画面的标准只有一句：**截一张图放进纪录片、产品照片或博物馆展板里不违和；家长一眼看上去不像动画片。** 由家长判定，agent 自己觉得像不算。

## 红线（任何一条不满足，就不能给孩子看）

1. **复杂物体只能来自素材文件，不能用代码拼。** 机器、机器人、动物、人、车辆、建筑、桥梁、植物这些“复杂物体”，必须是扫描、厂家 CAD、专业建模或依据真实照片生成的模型文件（GLB），或者实拍 / 预渲染的视频。代码里用 Box、Sphere、Cylinder、Capsule、Lathe、Torus、Cone、Tube、Extrude 等几何体拼出来的复杂物体，打光再好也不行。家长已经否掉三次：程序拼的螳螂虾、程序拼的工业机械臂、程序拼的接待机器人（都“像动画片”）。
2. **代码几何只允许用于真实形状本来就是简单几何的东西**：地面、积木方块、地砖、管子、绳子、卷尺带、样方框、玻璃板，以及点选用的隐形碰撞体和数学标注层。即使这样也必须用扫描或实拍来源的 PBR 贴图、有倒角、有磨损，不能纯色。
3. **主角必须是它本身。** 课讲博比特虫就出现博比特虫，讲机器人就出现真实的机器人。不用积木冒充机器人，不用螳螂虾的场景顶替别的动物，不能只在文字里提到它。真实画面没做好时，用授权的实拍照片或视频展示主角；连照片也没有，这节课等着，不发布。
4. **真实尺寸和真实动作。** 场景单位是米，物体按真实尺寸放；动作按真实速度和真实运动方式（机械臂按真实关节限位和速度，动物按真实视频里的动作）。放慢要标出倍数，例如“放慢 40 倍”。不用动画片手法：挤压拉伸、弹跳、夸张预备动作、拟人表情。
5. **来源可追溯、许可写清楚。** 每个素材登记来源网址、作者、许可、是否可商用、真实尺寸、参考照片、核对人。许可说不清的不用。现在是家用为主，以后要商用，家用许可的素材标 `commercial_ok: false`。
6. **依据照片生成的素材**（AI 图片、图生 3D、AI 数字人）要有至少 3 张真实参考照片，记录用的服务或模型，标注“AI 依据照片生成”，家长确认后才能用。
7. **家长确认才算数。** 素材从“待确认”变成“采用”只能由家长在家长端点按钮。agent 不能自己改成“采用”，也不能绕过确认。
8. **隐私。** 孩子的脸、声音、真实姓名、作业照片、学习记录、孩子说的话，不发给任何外部服务，也不用来做主持人形象。生成真人主持人只能用家长本人（书面同意）或有授权的成人形象。

## 工作流程（每做一个主角或场景都走一遍）

| 步骤 | 做什么 | 产出 | 细则 |
| --- | --- | --- | --- |
| 1 拆清单 | 从课的主题和数学动作拆出画面里要出现的每样东西：主角、环境、道具、测量工具、数学标注 | 场景清单（每项：类型、真实尺寸、要看的角度、要做的动作、写实等级） | [reference/pipeline.md](reference/pipeline.md) |
| 2 收集 | 先求全、不挑：实拍照片、视频、事实资料、所有 3D 来源候选、环境资料，各有最低数量 | `research/sources.json` | [reference/research.md](reference/research.md) |
| 3 理解 | 看完资料写说明：尺寸、结构、外观、怎么动、在哪里、孩子会觉得什么有意思、和数学怎么连、资料矛盾 | `research/brief.md` | [reference/research.md](reference/research.md) |
| 4 整理 | 有了理解才挑：精选参考照片，比较所有 3D 候选，定修改、动作、环境方案 | `research/plan.md` | [reference/research.md](reference/research.md)、[reference/asset-sourcing.md](reference/asset-sourcing.md) |
| 5 制作 | 统一成 GLB（PBR 贴图、真实尺寸、压缩），需要动的绑骨骼或关节；实时做不到的预渲染成视频 | `content/assets/<asset_id>/` 下的文件 + 登记 | [reference/realism-spec.md](reference/realism-spec.md) |
| 6 接进组件 | 按组件接口装进场景：热点锚点、动作、挑战配图、动手题、减少动态、释放资源 | 组件代码 + 测试 | [reference/component-contract.md](reference/component-contract.md) |
| 7 自检 | 跑自动检查，出对照图（我们的截图 vs 真实照片），过一遍自检清单 | 检查结果 + 对照图 | [reference/acceptance.md](reference/acceptance.md) |
| 8 家长确认 | 在家长端「素材确认」里看对照图和预览，点“确认可用”或写退回意见 | 素材状态“采用”或退回 | [reference/acceptance.md](reference/acceptance.md) |

第 2–4 步不能省、不能并成一步：**先收全、弄懂，最后才整理**。拿前几个搜索结果就开始做，是之前画面不像、主角不对的主要原因。

课末主持人（机器人或真人）的规格单独写在 [reference/host.md](reference/host.md)。现在仓库里哪些东西不达标、要换成什么，见 [reference/gaps.md](reference/gaps.md)，**动手前先读它**。

## 交付时必须给出

- 新增或替换的素材清单：资产 id、来源网址、许可、真实尺寸、面数、贴图尺寸、文件大小。
- 自动检查结果（全部通过才交）。
- 对照图：每个主角至少 4 个角度的截图和对应角度的真实照片并排，动作的 5 帧序列。
- 在家里 iPad 上的帧率和加载时间（做不到实测就写“未在 iPad 实测”）。
- 还没做到的地方，照实写。

## 绝对不要做

- 不用代码拼复杂物体，不拿别的东西冒充主角，不用卡通、低多边形、玩具风、表情脸。
- 不把不达标的画面先给孩子看着用。不达标的就不展示，换成实拍照片或视频。
- 不改校验器、测试或资产状态来让不达标的东西通过。
- 不把素材状态改成“采用”，不替家长确认，不发布课。
- 不把孩子的任何信息发到外部服务。
- 不用许可不清楚的素材；不把只限某个引擎使用的素材（例如只许在某引擎里渲染的数字人）导出到网页里用。
