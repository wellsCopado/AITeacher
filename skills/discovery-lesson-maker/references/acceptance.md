# 验收与交付

## 六条证据通道

先执行身份与功能审查：用户明确的人形、物种、建筑等对象不能被替换；核心结构各自有定位、作用、机制和可观察证据。缺少这一项时，数学题、旋转控制或文件测试通过都不能抵消。用`check_subject.py`核对scope记录，并实际查看当前完整主角与功能流程。

1. **文件和结构。** 本轮要求的模型、贴图和媒体文件存在、相对引用有效、来源校验一致、课程格式符合真实宿主。检查器不执行课程代码或导入JS来假装探测能力。
2. **科学和内容。** 关键事实来自读过的直接来源；数值保留对象、单位、条件与不确定性。重点检查会教给学生的部位、动作、尺度和问题答案。
3. **真实画面。** 最新反馈覆盖旧判断：本用户已进一步否定现机器人的真实感，不能再按早先“勉强过关”保留品质通过。素模/材质诊断仅帮助定位，还须对照实物并看实际Web。 先按[写实样段](visual-animation.md#写实样段先于整课)对照真实照片。用户已退回的版本记failed，不能以技术通过继续列为品质通过；新版本单独评价。实际运行中检查主角形体、关键部件、材质、光照、接触与动作，而不是另做几张漂亮宣传图。至少覆盖会用于教学的正侧/底部与关键动作阶段。
4. **交互流程。** 打开App课程 → 主角自由操作 → 按需动作/短片 → 题目操作 → 误答诊断 → 换一种表示 → 新任务验证 → 暂停/续学。检查失败时停止该完成声明，定位首个阻断后继续。Agent试课记录与孩子记录隔离，交付时不预置“已掌握”或把验收点击当成孩子学习。
5. **按需短片。** ffprobe等实测文件信息，抽查运动峰值及前后连续性，在宿主中播放；有旁白时核对声音和画面、字幕和事实。低帧率截图只能是QA记录。
6. **学习效果。** 技术通过不代表学生学会；仅能报告实际操作/答案/所用帮助。未真实试学就写未验证，不把家长观看画面变成教育效果证据。

测量课另核对单位与基线：同一物理高度换成厘米后位置应一致，表示高度差时要从相应基线起算。输入越界/清空、修改答案、切换表示时，旧通过与旧反馈不能继续有效。带着已放标记和已用帮助刷新页面，等资产重新载入后再核对，不能只在内存中试续学。

使用 `assets/production-template.json` 跟踪每条通道的 `pending/passed/failed/not-applicable` 和证据。`passed` 应有当前产物校验值、具体证据与检查说明；`not-applicable` 说明理由，不能用于跳过本轮必需的三维主角、动作、语音或短片。

## 检查器的范围

`check_production.py` 默认做制作资料的静态检查；`--stage assets` 要求真实三维主角、按本轮requirements约定的短片、可核实来源和来源许可；`--stage course` 再检查宿主状态、原生校验记录以及视觉/动作/交互/内容的证据记录。

输出里的 `checks` 与 `reviewStatus` 分开：静态结构通过不会自动修改任何视觉或学习状态。即使有人工填写的passed，程序也只确认记录和证据存在/校验一致，不能证明审美正确、操作实际发生或孩子掌握。

`check_challenges.py` 不取代App校验。不能仅凭它0错误声称已兼容目标App、做过三维操作或验证出教学效果。

## 交付

接 AI 探索世界 App 时，`scripts/check_package.py` 没有 errors 只说明包能被导入；还要在App里预览一遍：页面载入后“已核对 n/m 项”会变，点「休息 / 退出」声音和动画停下，退出再进能接着上。没能导入App时如实写“App 内未验证”。

课程制作时交付实际可导入内容、运行所需素材、场景和所需动作源码/绑定、所需媒体文件、来源与条款、制作记录、验收截图/视频。用户授权独立Web预览时交付可操作课程并保留宿主接入待验证；未授权预览且无宿主条件时交付素材/设计，不能冒称App已经可用。

制作包只包含明确选中的文件；保留原始素材和派生关系，排除密钥、账号缓存、依赖目录和私人资料。未来打包使用项目已授权方式，不假设本Skill有访问任何App或账号的权限。

本Skill安装/打磨交付只需Skill本身、必要脚本/模板、变更说明与技术验证；不因此额外开发播放器、课程或修改App。
