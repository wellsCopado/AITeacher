# 写实画面的通用做法（任何主题）

这份是做法，不绑定哪个主题。桥、虫子、火箭、机器人、海底都按同一套走：先定尺寸和参照，再拿扫描素材，再分“看”和“动手”两种画面各自做好，最后对着真实照片挑毛病。它补充 [画面与动画](visual-animation.md)（写实样段、素模诊断、返工分诊），不重复那里的规则。

来历：2026-11 用同一个桥梁模型做了两版画面。离线光线追踪（Blender Cycles）出的图接近建筑效果图；同一模型放进网页实时渲染，仍然像游戏。差别不在模型，而在光照、大气、水面和材质细节。所以“看”和“动手”要分开做、分开验收。

## 1. 两种画面：看用预渲染，动手用实时

| | 看（观察、讲解、开场、对比） | 动手（实验、拖动、摆放、判题） |
| --- | --- | --- |
| 画面来源 | 同一模型离线光线追踪出的图或短片（`scripts/render_stills.py`） | 网页里的实时三维（three.js），孩子的操作真的改变场景 |
| 目标 | 一眼像照片：光、雾、水、材质都对 | 操作跟手、状态正确，画面不出明显假感 |
| 验收用的图 | 预渲染图本身 | 网页实际截图（`scripts/shoot_views.mjs`），不能拿预渲染图代替 |

- 每一步在 `lesson-flow.json` 写 `media`：`render`（这一步给孩子看预渲染图/短片）或 `realtime`（这一步孩子在实时三维里动手）。有实验或动手题的步必须是 `realtime`。没写时按 `realtime` 算。
- 两种画面用**同一个模型文件和同一份机位表 `views.json`**，预渲染图和实时画面能一张对一张比较，孩子从图切到三维时不会觉得换了个东西。
- 预渲染不是偷懒的出口：没有一步实时动手的课不合格（家庭档案要求至少 3 个动手实验）。
- 实时画面达不到照片级是现状，不能因此跳过它的验收。实时画面要过第 4 节的毛病表，挑出的问题写进自评。

## 2. 按真实尺寸建模

- 先查主角和场景的真实尺寸，单位一律米。查不到就写“估计”和估计方法（比如按照片里的人或车的大小量出来）。写进 `visual_gate.dimensions`，每条带来源。
- 模型 1 单位 = 1 米。glTF 和 three.js 用 y 朝上。导出前在 Blender 里量一次关键尺寸，误差超过 5% 先改模型。
- 画面里放**尺度参照物**：人、车、门、树、硬币、手掌，选孩子熟悉的。没有参照物，大楼会像模型，虫子会像大怪兽。
- 数学题用到的数（长度、高度、数量）必须和模型尺寸一致。题里说 600 米，模型就是 600 米。

## 3. 素材从哪里来（按顺序试）

1. 家长或孩子已有的合格素材（实拍、扫描）。
2. 扫描的 CC0 素材：Poly Haven（模型、贴图、HDRI 天空）、ambientCG（贴图）。地面、岩石、植物、水边、树皮、混凝土、金属、沥青都先找扫描件，不用纯色或程序噪声。
3. 制造商、机构、博物馆公开的 CAD/BIM/3D 文件，或学术扫描（动物、化石）。许可写进来源。
4. 至少 3 张不同角度的真实照片做摄影测量或图生 3D，再修整。收费工具写进“需要家长决定”。
5. 照着有尺寸的参考在 Blender 里手工建模（建筑、桥、机械可以；动物、人不走这条）。

网络受限时（云端环境常见，Poly Haven、ambientCG 官网可能打不开）：

- Blender：`pip install bpy` 装 Blender 的 Python 版本（5.x），能无界面建模和用 Cycles 出图。`import bpy` 要在 `import bmesh` 前面。
- ambientCG 贴图：GitHub 上有镜像仓库（例如搜 `AmbientCG`），通常只有颜色图，用 `scripts/pbr_from_color.py` 补法线和粗糙度。
- HDRI：three.js 仓库 `examples/textures/equirectangular/` 里有 Poly Haven 的 1k HDR；npm 包 `@pmndrs/assets` 里有小尺寸 HDRI。
- 在家里的 Mac 上做课时直接从官网下全套贴图（颜色、法线、粗糙度、AO），比补出来的好，优先用。
- 打不开就写“未获取”，不拿别的主题的旧素材凑（这家人明确禁止复用别的课的素材）。

## 4. 假感毛病表

对着同角度的真实照片逐条看。看到就修，修不了写进自评。

| 看到的 | 常见原因 | 怎么修 |
| --- | --- | --- |
| 太新太干净，像塑料玩具 | 只有一张颜色贴图，没有污渍和磨损 | 加污渍、雨痕、锈迹、边角磨损贴图（低处和接缝更脏）；粗糙度要有变化 |
| 地面、墙面一格一格重复 | 同一张贴图平铺太多次 | 放大贴图尺度，混两张贴图，加大尺度的明暗变化遮住重复 |
| 周围是一堆方盒子 | 城市、街区用无贴图的体块 | 方盒只能放远处，压在雾里、调暗；近处换真实模型或扫描件；看得见的立面要有窗和贴图 |
| 水面像镜子或像果冻 | 反射太强、没有波纹、颜色太清 | 法线贴图做细浪，粗糙度别太低；河水偏黄绿、海水偏蓝绿；加船、波纹、岸边的浪 |
| 发白、灰蒙蒙或过曝 | 曝光、天空强度、雾的浓度一起调过了头 | 先关雾定曝光，再加雾；用 ACES/AgX 色调映射；太阳和天空亮度要匹配 |
| 远近一样清楚，没有空间感 | 没有大气透视 | 远处加雾或体积雾，颜色往天空色偏 |
| 细东西闪烁、断线（拉索、栏杆、天线、虫腿） | 实时渲染锯齿 | 开抗锯齿，细线稍加粗，远处换成贴图 |
| 物体飘在地上 | 没有接触阴影 | 打开阴影；接触处加 AO 或接触阴影 |
| 不知道有多大 | 画面里没有参照物 | 按第 2 节放人、车、手、门等 |
| 光照方向前后矛盾 | 太阳、天空图、反射来自不同方向 | 太阳方向和 HDRI 对齐，同一时刻 |

## 5. 工具（都是通用的，不带主题）

- `views.json`：机位表，网页和预渲染共用。y 朝上、单位米：
  ```json
  { "views": [ { "name": "overview", "position": [160, 22, 1150], "target": [-40, 85, 0], "fov": 42, "media": "render" } ] }
  ```
- `python3 scripts/pbr_from_color.py <颜色图…> --out <目录> [--size 1024] [--strength 1.5] [--roughness 0.85]`：只有颜色图时补出法线图和粗糙度图（`<名字>_color.jpg / _normal.jpg / _rough.jpg`）。`--water-normal` 另出一张能无缝平铺的水面法线图。补出来的比扫描原件差，能拿到原件就用原件。
- `python3 scripts/render_stills.py --input 模型.glb --views views.json --out 目录 [--sun-elevation 32 --sun-azimuth 140] [--hdri 天空.hdr] [--haze 0.00016] [--water 宽,长[,颜色]] [--samples 64] [--size 1280x750] [--only 名字,名字]`：用 Blender Cycles 按机位表出光线追踪图。有物理天空、太阳、大气雾和可选水面。默认只出 `media` 为 `render` 的机位，`--all` 全出（用来和实时画面对比）。
- `node scripts/shoot_views.mjs <网页地址> <输出目录> <views.json>`：用无头浏览器打开实时网页，逐个机位截图。网页要满足一个小约定：载入完设 `window.__ready = true`；提供 `window.adwSetView(view)` 切机位（参数就是 views.json 里的一项）。没有 GPU 的机器用软件渲染，会慢，但截图有效。

## 6. 验收

写进 `lesson-flow.json` 的 `visual_gate`，`scripts/check_package.py` 会查：

- `views`：对照图里用到的画面，每项 `{ "name", "media": "render" 或 "realtime", "file" }`。至少一张 `realtime`（孩子真正动手的那个画面）。课里有 `media: render` 的步，就至少要一张 `render`。
- `dimensions`：至少 1 条真实尺寸 `{ "what", "meters", "source" }`。
- `self_review`：照第 4 节逐条看过，写哪里像、哪里不像、怎么处理的。

对照图 `visual_gate.sheet` 把同角度的真实照片、预渲染图、实时截图并排。家长看的是这张图。技术检查过了只说明文件齐全，像不像由家长看图决定。
