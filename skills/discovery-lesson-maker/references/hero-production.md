# 主角三维：每个主题现做，做到能当真看

家长（2026-11-06）：“要根据主题去生产3d和制作课程”“不要老糊弄和不管主题，用素材硬套”。在这之前，家长已经退回过四次：

- 程序拼的螳螂虾；
- 圆柱方块拼的工业机械臂；
- 球和胶囊拼的接待机器人；
- 一张俯视照片做成的 2.5D 动物。

四次都“像动画片”。原因是同一个：主角不是来自真实的东西，而是制作者照着印象拼出来的。打光、加 4K 贴图都救不回来。

这一页规定**主角**（`research/assets.json` 里 `role: "hero"` 的那个三维模型）怎么做、怎么验。规则对任何主题都一样，没有为某个主题单独写的条款。主题和素材清单的规则见 [主题与素材](topic-assets.md)，光照、渲染和假感毛病见 [写实画面的通用做法](photoreal-pipeline.md)。

## 硬规则（检查器按这些拒收）

1. 主角先定**类别**（`class`），类别决定能从哪里来。动物和人只能来自实物：扫描、授权素材，或依据真实照片生成后再修整。动物和人不能手工建模，也不能程序生成。
2. 动手之前先收 **≥3 张不同角度的真实照片**。模型做好后，要和这些照片同角度对照。
3. 主角按**真实尺寸**放，1 单位 = 1 米。模型最长边和登记的真实尺寸差距不超过 10%。
4. 主角要有足够的细节，还要有真实的表面：三角形数不低于这一类的下限；≥80% 的面贴了颜色贴图；颜色贴图 ≥1024 像素；有法线或粗糙度贴图。纯色拼件、低多边形，一律不收。
5. 主角要经过**盲看**：把真实照片和本课画面打乱成 A/B，交给没参与制作的审看人。审看人看 3 个角度，都要认为是同一个东西，而且不像动画片、不像玩具。
6. 做不出合格的主角，这节课就**不交**。不拿别的课、App 自带场景、示例里的模型顶上，也不拿相近的东西冒充。

检查器能证明的只有一件事：主角不是代码拼的、不是纯色卡通件，而且有来源、尺寸对。像不像，由盲看和家长看对照图决定。

## 七步

### 第 1 步：定主角和类别

主角是主题里那个具体的真实东西。比如主题「鲸鱼」，主角写「蓝鲸（成年，约 25 米）」，不写「鲸鱼模型」。

| class | 是什么 | 例子 |
| --- | --- | --- |
| `organism` | 动物、昆虫、植物等生物 | 蓝鲸、工蜂、霸王龙骨架、向日葵 |
| `human` | 人 | 宇航员、消防员 |
| `machine` | 机器、机器人、机械臂 | 挖掘机、UR5e 机械臂、人形机器人 |
| `vehicle` | 车、船、飞机、火箭 | 地铁列车、长征二号F、帆船 |
| `structure` | 建筑、桥、隧道、塔 | 杨浦大桥、上海中心、盾构隧道 |
| `landform` | 山、火山、峡谷等地形 | 富士山、科罗拉多大峡谷 |
| `object` | 工具、器物等小物件 | 显微镜、算盘、指南针 |

一个主题有好几个主要东西时，让孩子动手最多的那个当主角。其余的是 `part` 或 `scene`，它们也不能代码拼复杂物体。

### 第 2 步：收真实照片和尺寸

- 找至少 3 张不同角度的真实照片，比如正面、侧面、俯视、关键部位近景。动物优先找博物馆标本照、科研照片和野外实拍，机器优先找厂家产品照，建筑优先找有拍摄位置的实景照。每张都记进 `research/sources.json`，写上网址、作者、许可和角度。
- 查真实尺寸，每条带来源，写进 `visual_gate.dimensions`。查不到就写“估计”，再写估计的办法。
- 先把资料收全、看懂，再挑素材。拿前几个搜索结果就开工，是以前主角不像的主要原因。

### 第 3 步：按类别选来源（从上往下试，找到合格的就停）

| 顺序 | 路线（`origin`） | 去哪找、用什么 | 能用于 |
| --- | --- | --- | --- |
| 1 | `scan`、`cc0-library`、`licensed`：现成的扫描和专业模型 | Smithsonian Open Access 3D、MorphoSource（标本）、Sketchfab（筛选可下载、看许可，搜“主角名 + scan / photogrammetry”）、Poly Haven（模型和植物）、NASA 3D Resources（航天器、火箭，公有领域）、各地博物馆开放数据 | 所有类别 |
| 2 | `cad`：厂家或机构的工程模型 | 厂家官网的 CAD（STEP、STL）、ROS 机器人描述包里的网格（例如 Universal Robots、Franka、KUKA 的 description 仓库，逐个核对许可）、GrabCAD（许可不一，逐个看）。STEP 用 FreeCAD 或 cadquery 转网格，再进 Blender 补材质 | machine、vehicle、structure、object |
| 3 | `generated`：依据真实照片生成，再修整 | 用第 2 步的照片生成。本机工具有 Hunyuan3D-2、TRELLIS（先看权重许可）；在线服务有 Tripo、Meshy、Rodin，收费的先问家长。生成后在 Blender 里修整：查附肢数、对称、底面，重新烘焙贴图 | 所有类别（动物和人只能走 1 或 3） |
| 4 | `modeled`：按有尺寸的图纸和照片手工建模 | Blender。曲面、倒角、接缝、磨损都要做，贴图用扫描贴图或照片投射 | machine、vehicle、structure、landform、object（不能用于动物和人） |
| 4 | `procedural`：按真实数据生成 | 地形用公开高程数据（USGS、Copernicus DEM），贴图用卫星影像，在 Blender 里生成。只用于地形 | landform |

**不能走的路**：

- 在网页代码里用 Box、Cylinder、Sphere、Capsule、Lathe 等几何体拼主角；
- 动物和人手工建模或程序生成；
- 拿别的课、App 固定场景、本 Skill 示例里的模型改改颜色当新主角；
- 用一张照片做成浮雕或卡片；
- 换成一个更好做的东西。

网络打不开第 1–3 条的网站时（云端环境常见），写“未获取”，交给家里 Mac 上的制作者去做。不要退到第 4 条去凑动物，也不要退到代码拼。

### 第 4 步：修整到能用

- 把真实尺寸摆好，1 单位 = 1 米，y 朝上。
- 统一成一个 `.glb`，贴图打包在里面。颜色贴图 ≥1024 像素，要有法线贴图，有粗糙度或 ORM 贴图。几何可以用 Draco 或 meshopt 压缩，贴图可以用 KTX2。
- 要动的部分绑骨骼或关节。动作按真实视频或厂家的关节限位和速度做，放慢时标出倍数。
- 随时自查：`python3 scripts/hero_check.py 模型.glb --class organism --size 25`。它查尺寸、面数和贴图，有 errors 就继续修。
- 用 `scripts/render_asset_diagnostics.py` 出素模图，看有没有玩具比例、零件悬空、附肢融合。

### 第 5 步：登记

在 `research/assets.json` 的主角那一项里，除了 [主题与素材](topic-assets.md) 要求的字段，还要写下面这些：

```json
{ "file": "web/dist/models/blue-whale.glb", "sha256": "…", "role": "hero", "depicts": "蓝鲸（成年）", "made_for": "鲸鱼",
  "class": "organism", "origin": "scan", "source_url": "https://3d.si.edu/…", "license": "CC0",
  "how": "史密森尼蓝鲸骨架扫描 + 体表按标本照片重建，Blender 修整、烘焙 2048 贴图",
  "real_size_m": { "length": 25.0 },
  "reference_photos": [
    { "source": "https://…/whale-side.jpg", "angle": "侧面", "license": "CC BY 4.0" },
    { "source": "https://…/whale-top.jpg", "angle": "俯视", "license": "CC BY 4.0" },
    { "source": "https://…/whale-fluke.jpg", "angle": "尾鳍近景", "license": "CC0" } ] }
```

AI 生成的主角还要写 `generator`（服务或模型的名字和版本），输入就是 `reference_photos` 里的照片。

### 第 6 步：盲看

1. 每个角度出一对图：一张真实照片，一张本课画面（预渲染图或实时截图），机位尽量一样。至少 3 个角度，其中至少一条拍主角近景（`subject: "hero"`）。
2. 把每对图随机标成 A 和 B，不告诉审看人哪张是照片。
3. 审看人不能参与过制作。可以是另一家的看图模型，比如做课用 Codex 时找 Claude 或 Gemini 看，反过来也行；也可以是家长。把下面这段原样发给审看人：

   > 这是同一个角度的两张图，A 和 B。请回答：1. 它们拍的是不是同一种东西？2. 哪张是真实照片？有多确定？3. 另一张看起来像什么：照片、看得出是电脑画面、动画片、还是玩具或模型？4. 列出让它看起来不真实的具体地方（比例、材质、颜色、光照、边缘、接触、背景）。

4. 把回答记进 `lesson-flow.json` 的 `visual_gate.blind_review`，每个角度一条：

```json
{ "view": "侧面", "subject": "hero", "media": "render", "photo": "research/ref-side.jpg", "ours": "evidence/render-side.png",
  "reviewer": "Claude（没参与制作）", "same_thing": true, "verdict": "photo", "flaws": [] }
```

`verdict` 是审看人对本课画面的判断，取值如下：

- `photo`：像照片。
- `cg`：看得出是电脑画面。实时动手的画面可以是 `cg`，但要在 `flaws` 里写出哪里不像；预渲染的“看”画面必须到 `photo`。
- `cartoon`：像动画片，不收。
- `toy`：像玩具或模型，不收。

不收的时候按 `flaws` 返工：

| 审看人说的 | 回到哪一步 |
| --- | --- |
| 不是同一个东西、比例不对、少了部件 | 第 3 步，换来源或重新生成 |
| 像塑料、颜色太纯、太干净 | 第 4 步，换扫描贴图，加磨损和粗糙度变化 |
| 光照、背景、阴影假 | 按 [写实画面的通用做法](photoreal-pipeline.md) 第 4 节的毛病表修 |

返工后**重新盲看**，不能改记录。审看人的原话不能删改。

### 第 7 步：做不出就不交

主角过不了检查或盲看时，在 `课程设计.md` 的缺口里写清楚三件事：

- 卡在哪一步；
- 试过哪些来源；
- 要什么才能做成，比如某个收费生成服务（附价格）、某个扫描的下载权限，或者一段真实视频。

整节课停在这里，告诉家长要什么。不交一节画面不合格的课。

## 检查器查什么

`scripts/check_package.py`（交课前）和 App 导入（App 自己做的课）用同一套规则。Python 版在 `scripts/hero_check.py`，App 版在 `apps/server/src/hero-check.ts`。

| 编号 | 查什么 | 不过时 |
| --- | --- | --- |
| H1 | 主角写了 `class` | error |
| H2 | `origin` 是这一类允许的路线（动物和人：`scan`、`cc0-library`、`licensed`、`generated`） | error |
| H3 | ≥3 张不同角度的真实照片。扫描、图纸、素材库、授权素材要有 `source_url`；AI 生成的要有 `generator` | error |
| H4 | `real_size_m` 写了，模型最长边和它相差 ≤10% | error |
| H5 | 三角形数 ≥ 下限：生物 15 000、人 20 000、机器和交通工具 12 000、建筑和地形 8 000、小物件 4 000 | error |
| H6 | ≥80% 的面贴了颜色贴图，颜色贴图 ≥1024 像素，有法线或粗糙度贴图；主角是 `.glb` | error |
| H7 | `visual_gate.blind_review` 有 3 个不同角度，其中至少一条是主角；审看人没参与制作；每条都认为是同一个东西；没有 `cartoon` 或 `toy`；预渲染的是 `photo` | error |

用真实文件试过：Khronos 的 DamagedHelmet（扫描级 PBR 头盔）能过；卡通 Duck 过不了，它的贴图只有 512 像素，没有法线和粗糙度贴图。

## 四个没做过的主题怎么走

下面只示范每一步落到什么，来源要到时候现查。

| | 鲸鱼（哥哥） | 地铁（妹妹） | 恐龙（哥哥） | 挖掘机（妹妹） |
| --- | --- | --- | --- | --- |
| 主角、class | 蓝鲸，organism | 上海地铁 A 型车一节，vehicle | 霸王龙骨架（博物馆展出的那具），organism | 一台真实型号的中型挖掘机，machine |
| 照片 | 侧面、俯视、尾鳍（科研和博物馆照片） | 车头正面、侧面、车厢内部 | 正面、侧面、头骨近景 | 正面、侧面、铲斗近景（厂家产品照） |
| 路线 | 1：博物馆扫描；不行就 3：照片生成后修整 | 2：厂家外形图做 CAD；不行就 4：按图纸建模，配扫描贴图 | 1：化石骨架扫描 | 2：厂家 CAD；不行就 4：按尺寸图建模 |
| 真实尺寸 | 约 25 米 | 车长约 22.8 米 | 约 12.3 米 | 按型号查，约 9.5 米 |
| 不能这样做 | 用球和圆柱拼一条鲸，或拿螳螂虾的海底凑 | 用方盒子当车厢，拿机器人工厂的传送带凑 | 用卡通恐龙、玩具模型凑 | 用积木或旧机械臂改色 |

这几个主题都在 `tests/test_hero.py` 里各走了一遍。代码拼的、纯色的、尺寸错的、动物手工建模的、没有照片的、盲看说像动画片的，都会被拒收。夹具只是测试用的 `.glb`，不证明画面合格。

## 和 App 自带场景的关系

参数课里那三样代码做的东西已经下线，被这条流程代替（`skills/photoreal-3d-production/reference/gaps.md` 的 G1–G3）：

- **机器人工厂的机械臂**：机器人、机械臂、工厂主题都改做探索课，主角走第 3 步第 2 条，用厂家 CAD。
- **接待机器人主持人**：已关掉，课末聊天只用文字、字幕和朗读。
- **2.5D 动物浮雕**：已关掉，动物用实拍照片和视频展示，等合格的三维主角出来再用。
