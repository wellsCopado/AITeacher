# 接入已有App

本Skill描述课程生产和验收，不强制一个固定播放器。按当前用户要求选择接入已有App或制作独立Web预览；历史某一轮“只做Skill”的限制不能覆盖用户后来明确授权制课的请求。

**接 AI 探索世界 App 时**先读 [App 参考](app-reference.md)：那里已经有现成的接入方式（探索课包 + `adw-host.mjs`），不用另找接口。交之前跑 `scripts/check_package.py`；导入后家长在App里预览、走通“载入 → 进度 → 休息/退出 → 接着上”，这时 `app.status` 才可以写 passed，证据是导入返回的 `key`/`warnings` 和实际走课记录。下面是接其他宿主时的通用做法。

用户明确允许本机任意地址时，直接制作独立预览，保留原App不变。独立预览要走完打开、三维观察、动作/短片、答错帮助、新题和续学流程；构建通过不等于浏览器流程通过，更不等于原App接入通过。原生`course`检查仍用于宿主交付；独立预览在实际记录中单列构建和浏览器证据，`app.status`保持`pending`，不为让检查器变绿而填写假兼容性。

## 先读真实契约

按已提供的路径或连接读取App的AGENTS、当前课程样例、内容Schema、组件目录、场景API、原生校验与运行说明。已有CLI时先读其帮助/文档，确认命令存在再执行；不能凭补充材料一句 `dls context` 猜测已安装或宣称已经连接。

记录：

- 使用的App/组件版本或源码摘要、样例和Schema位置；
- 已确认的学科主线、年龄/学情、语言、题型和流程配置；
- 每种交互对应的实际控制器/状态、单位、边界和释放方式；
- 原生内容校验、真实运行测试和导入方式。

没有App源码/接口时可以研究主题、准备资产和教学设计，但 `app.status` 必须保留 `pending`，不能把“JSON合法”写成“可导入App”。不为适配方便重写宿主，新增组件或改流程按本次授权范围处理。

## 能力是可观察语义，不是一套强制函数名

| 语义 | 验收证据 |
| --- | --- |
| 真实三维观察 | 实际网格；自由旋转、缩放和透视遮挡变化 |
| 底部观察 | 原场景可提起/翻面/归位；不穿地、不强制跳到静态图页 |
| 动作控制 | 相关部件确实动作；暂停、重放、慢放或阶段观察可用 |
| 参数操作 | 直接拖动与UI控制改变同一真实状态，范围和单位一致 |
| 操作判题 | 读取场景的最终状态/连接关系，符合题意条件，区别多解和有序答案 |
| 生命周期 | 加载失败可见；切课后释放，重新进入能恢复；暂停不偷跑模拟 |
| 短片 | 宿主能播放真实文件，有控制与字幕/说明；不将视频当自由视角 |

把这些语义映射到App已有方法，不要求宿主必须实现某个任意签名。静态GLB、绑定源码、动画片段分别列明。App只支持参数build时，不在课程里塞未经实现的组装或旋转判题。

## 制作记录与App内容分开

`production.json` 只记录制作范围、文件、核实、能力和证据，不是新的课程Schema。真正的课程JSON写成宿主支持的格式，原生校验后再导入。

`check_challenges.py` 只是按提供的 `challenge-types.md` 作预检，支持 `--pointer` 指定实际题目数组的位置。能力JSON可以来自真实App导出或人工摘录；附带示例明确为文档摘录，不能当运行时探测结果。预检不能冒称V09/V20/V21等已运行。

预检脚本接受 `examples/capabilities.example.json` 所示的规范化摘录：`params` 只列操作题的数值参数及min/max/step/unit，`handsOn.<type>.controls` 列可改参数。原始 `components.json` 和 `dls context` 结构不同，先按实际Schema映射，不能直接替换输入文件或丢掉范围限制。`runtimeVerified` 只有实际运行验证后才可改为true。

## 不让内容替App造假

原生流程若只存到阶段、不存具体题目，Skill不能声称精确续学；若只有UI变量、没有场景读回接口，不能宣称操作判题可信。记录这些集成阻断，给出最小需要的接口改动；在用户只授权做Skill时不擅自修改App。
