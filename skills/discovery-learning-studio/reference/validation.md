# 自动校验 V01–V21

`dls validate` 输出每条规则的结果；✗ 为错误（阻止发布），! 为警告。

| 规则 | 检查 | 常见修法 |
| --- | --- | --- |
| V01 | Schema 和组件参数 | 按报错路径补字段、改类型；参数超出组件范围就收窄 |
| V02 | 参考算例、安全公式 | 改正期望值；补越界算例；公式只用四则运算 |
| V03 | teaches 引用合法 | 只能引用主知识点、它的误区或前置知识点 |
| V04 | 中文讲解 | 每个热点写一条中文 |
| V05 | 讲解固定 1 中 3 英 | `cycle_enabled: true`，每个热点英文写满 3 条；没有纯中文模式 |
| V06 | 已审组件、无代码 | 换白名单组件；删掉 HTML、脚本 |
| V07 | 素材登记与许可 | 先登记资产库；待采购的移到 pending |
| V08 | 教材映射 | 没核对就用“参考·待核对” |
| V09 | 迁移题 | 加 transfer 节点，至少一道 `with_theme: false` |
| V10 | 重教换教法 | 换组件或活动结构，并加 contrast 节点 |
| V11 | 商用素材 | 商用发布前替换仅家用素材 |
| V12 | 仅家用提示（警告） | 告诉家长，商用前替换 |
| V13 | 写实底线 | 删掉卡通或简化素材；生物用 scan/photo/ai_from_photo；待采购写“不展示” |
| V14 | 兴趣与心愿 | 原样用 `suggested_theme`（家长指定的主题或这个孩子自己的兴趣），或设 neutral；用 `dls theme --write` 生成心愿问题；删掉养殖经营内容 |
| V15 | 同一机制连续 3 次重教未见效 | 换一个组件或表征；没有合适组件就请家长开组件工单。重教历史由 `dls sync` 从服务器拉到 `content/reteach.json` |
| V16 | 每步时间上限 | `timing.steps` 里各步秒数（explain/demo/challenge/chat）加起来不超过 `est_minutes` 上限；不写就按预计时长自动分配 |
| V17 | 错三次演示 + 同类题 | 每道题写 `worked_example.steps`（2–5 步，最后一步说出全部答案）和 `twin`（换数字或情境，`field` 与原题一致，选择题的同类题也带 `options`） |
| V18 | 坚持的理由 | 写 `encouragement.persist` 至少 2 句，和主题相连；“真棒”“加油”这种空话不算 |
| V20 | 题型（警告） | 挑战题以选择题和应用题为主，没有选项的填空题最多 1 道，选项 2–4 个；组件支持动手题时至少 1 道动手题。见 [challenge-types.md](challenge-types.md) |
| V21 | 动手题能做 | `task` 的参数是组件允许孩子改的；`start` 写全、在范围内、不等于答案；答案正好一个 control 一条、范围内整数；不写 `options`；同类题也是动手题。见 [challenge-types.md](challenge-types.md) 第 4 节 |
| V19 | 主角要看得到 | 主题有主角（`theme.subject`）时，把它列进 `pending_assets`（系统会自动补），标题或说明页标题里写出它的名字；画面做好、家长确认后才能发布 |
